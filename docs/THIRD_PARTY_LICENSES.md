## 1. Policy

| License type | Examples | Policy |
|---|---|---|
| Permissive | MIT, BSD, Apache 2.0, ISC | Allowed |
| Weak copyleft | LGPL, MPL 2.0, EPL | Allowed with approval from [role]. Use as a separate library only. |
| Strong copyleft | GPL, AGPL | Not allowed in shipped code without legal approval |
| Source available or custom | BSL, SSPL, Commons Clause | Needs legal review |
| No license | Missing license file | Not allowed. Without a license you have no right to use it. |
| Data and models | Dataset or model licenses | Check usage terms. See [ml/MODEL_CARD.md](ml/MODEL_CARD.md). |

## 2. Rules for Adding a Dependency

1. Check the license against the table above.
2. Check that it is maintained: a release in the last 12 months and an active issue tracker.
3. Check for known vulnerabilities.
4. Prefer a small, well known package over many tiny ones.
5. Explain why it is needed in the pull request.
6. CI fails the build for blocked licenses.
